# C19 安全針具使用情形查檢表（`SafeNeedle`）

## 1. 功能定位

- 樹狀選單 Key：`C19`
- 顯示名稱：安全針具使用情形查檢表
- 核心程序：`module/OpdAccRpt/Module1.bas` 的 `SafeNeedle`
- 呼叫入口：`source/OpdAccRpt/FrmTreeView.frm` 的 `CmdPreview_Click`
- 輸入：單一日期、門急診／住院來源、選填的護理站／床號前綴
- Oracle 輸入表：`OpdOrdTbl`/`IpdOrdTbl` 與 `OpdBasicTbl`/`IpdBasicTbl`
- Access 暫存：`C:\Tch\Report\OpdAccRpt\ReportDB.mdb` 的 `SafeNeedleTbl`
- Crystal 輸出：`C:\Tch\Report\OpdAccRpt\ipdsafeneedle.rpt`

## 2. 畫面與參數流程

`Form_Load` 建立 C19：

```vb
Set nodX = TreeView1.Nodes.Add("R", tvwChild, "C19", "安全針具使用情形查檢表")
```

- 啟用 `TxtConsulting`。

按預覽後先由來源選項設定：


再分派：

```vb

                    Trim(TxtDate_End.Text), _

```

## 3. 前置驗證與副作用

程序依序執行：

1. `IsDate7(strSDate)` 驗證起始日，不通過顯示「日期格式錯誤!!」。
2. 要求 `strSDate = strEDate`，否則顯示「僅限查詢一天資料!!」。
3. 開啟部署目錄的 `ReportDB.mdb`。
4. 無條件執行 `DELETE FROM SafeNeedleTbl`。
5. 開啟空 DAO Recordset：`SELECT * FROM SafeNeedleTbl WHERE 1=2`。
6. 執行 Oracle CTE 查詢，逐筆寫入 Access。
7. 呼叫 Crystal Report 預覽。

這表示報表暫存表是全域共享且「先清空再重建」，沒有使用者或批次識別。兩位使用者同時執行時可能互相清除或混用資料，也沒有 transaction 保護。

## 4. 安全針具醫令分類

查詢只接受下列 11 個 `chop4ordno`：

| 分類 | 醫令碼 | 版面處理 |
| --- | --- | --- |
| `X` | `SICPU24`, `SICPU22`, `SICPU20`, `SICPU19`, `SICPU18`, `SICTEF20` | 每兩筆拆到輸出第 1、2 欄 |
| `Y` | `SDS3`, `SDS0.5`, `SSN23S`, `SDS1`, `SDS3B` | 每筆放輸出第 3 欄 |

歷史修改：

- 初版 X 類沒有 `SICTEF20`，2016-04-06（民國 105）加入。
- 初版清單沒有 `SDS1`，後續加入。
- 現行清單再包含 `SDS3B`。

程式只按代碼分類，不連 `GenOrdBasicTbl` 取得名稱，也不計算醫令數量；每一筆 distinct 病患／醫令／輸入日組合視為一個列印項目。

## 5. 實際 SQL（依原始碼整理）

以下 `{OrdTbl}`、`{BasicTbl}` 分別代表 `OpdOrdTbl`/`IpdOrdTbl` 與 `OpdBasicTbl`/`IpdBasicTbl`；`:reportDate` 是同一天的民國 7 碼日期；`:stationPrefix` 是選填條件。

```sql
WITH tmp_a1 AS (
    SELECT chop1date AS a01k,
           chop1time AS a02k,
           chop1room AS a03k,
           intop1no  AS a04k,
           CASE
             WHEN chop4ordno IN
                  ('SICPU24','SICPU22','SICPU20','SICPU19','SICPU18','SICTEF20')
             THEN 'X' ELSE 'Y'
           END AS ordno_a,
           SUBSTR(chop4idate, 1, 7) AS chop4idate_a,
           chop4ordno AS chop4ordno_a
    FROM {OrdTbl}
    WHERE chop4idate BETWEEN :reportDate || '0000'
                         AND :reportDate || '9999'
      AND (chop4dcdate NOT BETWEEN :reportDate || '0000'
                               AND :reportDate || '9999'
           OR RTRIM(chop4dcdate) IS NULL)
      AND chop4ordno IN
          ('SICPU24','SICPU22','SICPU20','SICPU19','SICPU18','SICTEF20',
           'SDS3','SDS0.5','SSN23S','SDS1','SDS3B')
      AND (chop4stat <> 'DC' OR RTRIM(chop4stat) IS NULL)
),
tmp_a2 AS (
    SELECT DISTINCT
           a.ordno_a,
           a.chop4idate_a,
           a.chop4ordno_a,
           b.chop1ebid  AS chop1ebid_a,
           b.chop1mrno  AS chop1mrno_a,
           b.chop1pname AS chop1pname_a
    FROM tmp_a1 a
    JOIN {BasicTbl} b
      ON a.a01k = b.chop1date
     AND a.a02k = b.chop1time
     AND a.a03k = b.chop1room
     AND a.a04k = b.intop1no
    -- 有輸入 station 時，原碼把 BasicTbl 替換為以下 inline view：
    -- JOIN (SELECT * FROM {BasicTbl}
    --       WHERE chop1ebid LIKE :stationPrefix || '%') b
),
tmp_b AS (
    SELECT ordno_a, chop4idate_a, chop4ordno_a,
           chop1ebid_a, chop1mrno_a, chop1pname_a,
           ROW_NUMBER() OVER (
             /* 住院：PARTITION BY SUBSTR(chop1ebid_a,1,3), ordno_a */
             /* 門急診：PARTITION BY ordno_a */
             ORDER BY chop1ebid_a, chop1mrno_a,
                      chop4ordno_a, chop4idate_a
           ) AS rn_b
    FROM tmp_a2
),
tmp_c AS (
    SELECT tmp_b.*,
           CASE WHEN ordno_a = 'X' THEN CEIL(rn_b / 2) ELSE rn_b END AS rowset1_c,
           CASE WHEN ordno_a = 'X'
                THEN DECODE(MOD(rn_b, 2), 0, '2', MOD(rn_b, 2))
                ELSE '1'
           END AS rowset2_c
    FROM tmp_b
),
tmp_d1 AS (
    SELECT * FROM tmp_c WHERE ordno_a = 'X' AND rowset2_c = '1'
),
tmp_d2 AS (
    SELECT * FROM tmp_c WHERE ordno_a = 'X' AND rowset2_c = '2'
),
tmp_d3 AS (
    SELECT * FROM tmp_c WHERE ordno_a = 'Y' AND rowset2_c = '1'
)
-- 最終 SELECT 依住院／門急診使用不同對齊條件，見下一節。
```

## 6. 每個 CTE 的邏輯

### `tmp_a1`：挑出有效醫令

- `chop4idate` 必須落在查詢日 `0000`～`9999`，所以依醫令輸入日期時間選取。
- 若 `chop4dcdate` 也落在同一天，該醫令被排除；取消日空白則保留。
- `chop4stat='DC'` 被排除；NULL／尾端空白保留。
- 保存就醫複合鍵：日期、時間、診間、序號。
- 將醫令分成 X（六種）與 Y（五種）。

`NOT BETWEEN ... OR IS NULL` 的結果是：前一天或後一天取消的醫令仍可能保留，只有「同日取消」被排除。這是否符合安全針具統計定義，移植前應由業務確認。

### `tmp_a2`：連回病患資料並去重

- 以四欄就醫鍵連接 BasicTbl。
- 取得床號、病歷號、姓名。
- 有站別條件時，以 `chop1ebid LIKE '{strStation}%'` 過濾。
- `DISTINCT` 消除完全相同的分類、日期、醫令碼、床號、病歷號、姓名；相同病患使用不同醫令碼仍保留多筆。

### `tmp_b`：各分類編流水號

- 住院：依床號前三碼（護理站）及 X/Y 分類各自重新編號。
- 門急診：只依 X/Y 分類重新編號，不按站別。
- 排序鍵為床號、病歷號、醫令碼、醫令日期。

### `tmp_c`：把 X 類兩筆一組

- X 類的第 1/2 筆同屬 `rowset1_c=1`，第 3/4 筆同屬 2，以此類推。
- 奇數筆標為 `rowset2_c='1'`，偶數筆為 `'2'`。
- Y 類一律標為第 1 子欄，`rowset1_c=rn_b`。

### `tmp_d1`～`tmp_d3`：三個列印欄位資料源

- `d1`：X 類奇數筆。
- `d2`：X 類偶數筆。
- `d3`：Y 類全部資料。

## 7. 最終三欄式輸出

每一輸出列包含 A/B/C 三組相同結構：醫令日、醫令碼、床號、病歷號、姓名、站別。

### 7.1 住院分支

```sql
SELECT d1.chop4idate_a AS chop4idate_1,
       d1.chop4ordno_a AS chop4ordno_1,
       d1.chop1ebid_a  AS chop1ebid_1,
       d1.chop1mrno_a  AS chop1mrno_1,
       d1.chop1pname_a AS chop1pname_1,
       COALESCE(SUBSTR(RTRIM(d1.chop1ebid_a),1,3),
                SUBSTR(RTRIM(d2.chop1ebid_a),1,3),
                SUBSTR(RTRIM(d3.chop1ebid_a),1,3)) AS station_1,
       d2.chop4idate_a AS chop4idate_2,
       d2.chop4ordno_a AS chop4ordno_2,
       d2.chop1ebid_a  AS chop1ebid_2,
       d2.chop1mrno_a  AS chop1mrno_2,
       d2.chop1pname_a AS chop1pname_2,
       COALESCE(SUBSTR(RTRIM(d1.chop1ebid_a),1,3),
                SUBSTR(RTRIM(d2.chop1ebid_a),1,3),
                SUBSTR(RTRIM(d3.chop1ebid_a),1,3)) AS station_2,
       d3.chop4idate_a AS chop4idate_3,
       d3.chop4ordno_a AS chop4ordno_3,
       d3.chop1ebid_a  AS chop1ebid_3,
       d3.chop1mrno_a  AS chop1mrno_3,
       d3.chop1pname_a AS chop1pname_3,
       COALESCE(SUBSTR(RTRIM(d1.chop1ebid_a),1,3),
                SUBSTR(RTRIM(d2.chop1ebid_a),1,3),
                SUBSTR(RTRIM(d3.chop1ebid_a),1,3)) AS station_3
FROM tmp_d1 d1
FULL OUTER JOIN tmp_d2 d2
  ON SUBSTR(d1.chop1ebid_a,1,3) = SUBSTR(d2.chop1ebid_a,1,3)
 AND d1.rowset1_c = d2.rowset1_c
FULL OUTER JOIN tmp_d3 d3
  ON SUBSTR(d1.chop1ebid_a,1,3) = SUBSTR(d3.chop1ebid_a,1,3)
 AND d1.rowset1_c = d3.rowset1_c
ORDER BY SUBSTR(d1.chop1ebid_a,1,3), d1.rn_b,
         SUBSTR(d2.chop1ebid_a,1,3), d2.rn_b,
         SUBSTR(d3.chop1ebid_a,1,3), d3.rn_b;
```

站別取該列三欄中第一個非 NULL 床號的前三碼，並複製到 `station_1/2/3`。

### 7.2 門急診分支

門急診輸出欄位相同，但三個 station 欄固定為 `'ER'`；join 不比較床號前三碼：

```sql
FROM tmp_d1 d1
FULL OUTER JOIN tmp_d2 d2
  ON d1.rowset1_c = d2.rowset1_c
FULL OUTER JOIN tmp_d3 d3
  ON d1.rowset1_c = d3.rowset1_c
ORDER BY d1.rn_b, d2.rn_b, d3.rn_b
```

這裡的「門急診」沒有像 C18 額外限制 `chop1room='0000'`，所以實際資料範圍取決於 `OpdOrdTbl` 中符合醫令碼的所有門／急診資料；報表站別卻一律顯示 ER。

## 8. Access `SafeNeedleTbl` 欄位映射

Oracle 每一列被逐筆 `AddNew` 寫入 18 欄：

| Oracle 結果 | Access 欄位 | 意義 |
| --- | --- | --- |
| `chop4idate_1` | `chop4idate_a` | A 欄醫令日 |
| `chop4ordno_1` | `chop4ordno_a` | A 欄醫令碼 |
| `chop1ebid_1` | `chop4ebid_a` | A 欄床號；Access 欄名中的 `chop4` 與來源命名不一致 |
| `chop1mrno_1` | `chop1mrno_a` | A 欄病歷號 |
| `chop1pname_1` | `chop1pname_a` | A 欄姓名 |
| `station_1` | `station_a` | A 欄站別 |
| 對應 `_2` 六欄 | 對應 `_b` 六欄 | B 欄 |
| 對應 `_3` 六欄 | 對應 `_c` 六欄 | C 欄 |

所有值都以 `Trim("" & field)` 寫入：NULL 會變空字串，其他值去掉前後空白。報表因此無法再區分資料庫 NULL 與真正的空字串。

## 9. Crystal Report 流程

```vb
ObjCryRpt.ReportFileName = bcOpdStatsPath & "ipdsafeneedle.rpt"
ObjCryRpt.Destination = crptToWindow
ObjCryRpt.Action = 1
```

`bcOpdStatsPath` 固定為 `C:\Tch\Report\OpdAccRpt\`。目前 repository 的 `report/OPDACCRPT/` 內有 `ReportDB.mdb`，但沒有 `ipdsafeneedle.rpt`，所以只能確認程式資料流與暫存欄位，無法由此 checkout 核對 Crystal 內的分組、公式、標題、紙張與資料庫位置設定。正式移植前需從授權部署環境補齊該 `.rpt`。

即使 Oracle 查無資料，程式只顯示「查無資料!!」，隨後仍會打開空白 Crystal 報表，因為沒有在 `.EOF` 分支 `Exit Sub`。

## 10. 邏輯風險與疑點

- **FULL OUTER JOIN 鏈結疑點**：第二次 join 永遠用 `d1` 當鍵。若某站／列只有 `d2` 而沒有 `d1`，同鍵的 `d3` 不會與它合併，可能形成兩列。SQL 若要穩定對齊，應以 `COALESCE(d1 key, d2 key)` 連 `d3`。
- **尾端奇數通常有 d1**：X 類由奇數筆進 d1，因此正常編號下 d2 不太可能單獨存在；但 FULL JOIN 的寫法仍脆弱，且不同站的分組／資料異常時需實測。
- **住院 ORDER BY 以 d1 優先**：只有 d2/d3 的列，其 d1 排序鍵為 NULL，最終站別順序可能不直觀。
- **站別長度固定三碼**：`SUBSTR(chop1ebid,1,3)` 是硬編碼規則；新床號格式若不同會錯分。
- **條件未 escape**：`strStation` 直接串入 `LIKE`，單引號會使 SQL 失敗，`%`、`_` 會成為萬用字元，也存在 SQL injection 風險。
- **日期驗證不對稱**：只驗證起日；迄日只要求字串相等。雖相等時可間接成立，設計仍不清楚。
- **取消判斷語意**：排除同日取消及 `stat='DC'`，但其他日期取消仍保留。
- **共用 MDB 競爭**：先 DELETE、再逐筆 INSERT、最後讀取，沒有 transaction、鎖定或批次 ID。
- **例外清理不足**：沒有 `On Error` 清理區塊；中途錯誤可能留下開啟的 ADO/DAO 物件與半套暫存資料。
- **報表資產缺失**：repo 無 `ipdsafeneedle.rpt`，無法保證現有 MDB schema 與部署報表完全一致。

## 11. 維護／移植時的等價實作建議

1. 保留單日限制，將日期轉成明確型別並以 bind parameter 查詢。
2. 將安全針具代碼做成設定表或至少具名常數，記錄 X/Y 分類與有效期間。
3. 將站別條件參數化；先釐清 UI 應顯示「護理站／床號前綴」而不是「診間號」。
4. 可直接產生報表資料模型，避免共享 Access 表；若必須相容 Crystal，至少加入批次 ID、transaction 與使用者隔離。
5. 重寫三欄對齊時，以 `(station, rowset1)` 作完整 key；門急診以 `(ER, rowset1)`，再分別 left join 三個資料集，避免 chained full join 的 NULL key 問題。
6. 驗證 X 類 0/1/2/3 筆及 Y 類 0/1/多筆的排列，並涵蓋只有 X、只有 Y、不同護理站、空床號、奇數筆等邊界。
7. 從正式部署環境取得 `ipdsafeneedle.rpt`，核對 `SafeNeedleTbl` 18 欄型別、分組、公式、欄位位置及頁面小計。

## 12. 建議驗證案例

| 案例 | 應核對內容 |
| --- | --- |
| 同站 X 類 1 筆 | 只進 A 欄，B 空白 |
| 同站 X 類 2 筆 | 同列進 A、B |
| 同站 X 類 3 筆 | 第 3 筆進下一列 A |
| 同站 Y 類多筆 | 依流水號逐列進 C |
| 不同護理站 | 住院分站排列，不可跨站配成同列 |
| 有 station 前綴 | 只保留 `chop1ebid LIKE prefix%` |
| 同日取消 | 應排除 |
| 非同日取消 | 依原程式仍保留，需業務確認 |
| `chop4stat='DC'` | 應排除 |
| 查無資料 | MDB 被清空，程式仍開啟空白報表 |
| 兩位使用者同跑 | 檢查共享 MDB 的互相覆寫問題 |
