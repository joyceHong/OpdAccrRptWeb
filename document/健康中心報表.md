### 2.1 樹狀節點

來源：`FrmTreeView.frm:1298-1310`。

### 2.2 畫面條件

C171～C174 被放在 `TreeView1_NodeClick` 的共用簡易報表分支中。選取時：

- 只保留起始日期與迄止日期。
- 起始/迄止時間被停用並清空。
- 批價人員、科別、新科別、診間、門急診別、合約單位、病歷號、收費科目、批價碼全部停用。
- 重跑選項隱藏。
- 門診/住院來源選項隱藏，並把 `optSource(0)` 設成門診。

因此四張報表的使用者輸入實際上都只有日期區間。雖然 C171～C173 的程序簽章仍保留 `CrystalReport As CrystalReport`，程序內完全沒有使用該參數；四張報表最後都走 Excel，而不是 Crystal Report。

### 2.3 預覽前檢核

`CmdPreview_Click` 執行下列檢查：

1. 必須選擇一個報表節點。
2. 起始日期與迄止日期不得為空。
3. 使用 `Val(起始日期) <= Val(迄止日期)` 比較日期先後。
4. 對這四張報表不檢查時間，因為時間欄位已停用。
5. 停用預覽按鈕並顯示忙碌游標。
6. 依 Key 呼叫對應程序。
7. 完成後恢復按鈕與游標。

分派程式：

```vb

    Call HealthCenter(Trim(TxtDate_Start.Text), Trim(TxtDate_End.Text), CrystalReport)
Case "C172"
    Call HealthCenter1(Trim(TxtDate_Start.Text), Trim(TxtDate_End.Text), CrystalReport)
```

日期檢核只檢查空白及數值大小，沒有驗證固定 7 碼、月份、日期是否合法。SQL 又是直接串接字串，若新版移植應改為格式驗證加參數化查詢。

## 3. 共用資料存取與 Excel 輸出

### 3.1 `CGetData.GetDataRS`

四個程序都建立 `CGetData`，並以相同方式執行 SQL：

```vb
Set adoResult = objData.GetDataRS(SQL, , , mADOCn)
```

第四個參數傳入既有的 `mADOCn`，所以 `CGetData` 不另開連線，而是直接使用主程式已建立的 Oracle ADO Connection。內部以 `ADODB.Command` 執行：

```vb
With ADO_COM
    .ActiveConnection = pCn
    .CommandType = adCmdText
    .CommandTimeout = 600
    .CommandText = sSQL
    Set GetDataRS = .Execute
End With
```

特性與注意事項：

- SQL timeout 為 600 秒（10 分鐘）。
- 沒有使用 `ADODB.Parameter`，所有日期都已先串入 SQL。
- 查詢錯誤由 `Err.Raise` 重新拋出，四個報表程序本身沒有區域錯誤清理區段。
- `pCn` 最後只設為 `Nothing`，不關閉傳入的共用連線，這是正確的共用連線生命週期行為。

### 3.2 Excel 可用性檢查

四個程序一開始都呼叫 `subIsExcel2000`：

```vb
Set objExcelApp = CreateObject("Excel.Application")
If Err.Number <> 0 Then
    MsgBox "請確認本電腦有安裝Excel！！", vbInformation
Else
    objExcelApp.Quit
End If
```

它只是嘗試建立 Excel COM 物件並提示錯誤，沒有回傳 Boolean，也不會阻止後續 SQL 或 `subExcel`。因此 Excel 未安裝時，後續仍可能再發生錯誤。

### 3.3 `subExcel` 匯出流程

如果 Recordset 不是 EOF，四個程序都呼叫：

```vb
Call subExcel(strSDate & "~" & strEDate, adoResult, "")
```

匯出步驟：

1. 建立並顯示 `Excel.Application`。
2. 建立只含一張工作表的新 Workbook。
3. 將工作表名稱設為 `起日~迄日`。
4. 第一列逐欄寫入 ADO Field Name；SQL 的中文 alias 就成為 Excel 表頭。
5. 從第 2 列第 1 欄開始呼叫 `CopyFromRecordset`，一次匯入全部資料。
6. 自動調整目前區域的欄寬與列高。
7. 因 `strFilePath=""`，不自動存檔、不關閉 Excel，讓使用者自行檢視與另存。

若查無資料，則顯示 `查無資料!!`，關閉 Recordset，釋放 `Recordset` 與 `CGetData` 參考。

- 開單醫師：`chOp3DriD`。

- 六類金額：`rlOp3Sub1 ... rlOp3Sub6`。

## 5. C171 健康管理中心明細資料

### 5.1 功能目的

C171 將健康管理中心相關的「醫令」與「藥品」明細合併，輸出到同一張 Excel。它不是彙總報表；每一列代表一筆批價醫令或藥品項目。

### 5.2 重組後 SQL

```sql
SELECT
    RTRIM(o.chop4pfin2)      AS 記帳代碼,
    RTRIM(t.chdcttypename)   AS 記帳名稱,
    RTRIM(s.chnewsecno)      AS 責任中心代碼,
    RTRIM(o.chop4drid)       AS 開單醫師代碼,
    RTRIM(o.chop4exedrid)    AS 執行醫師代碼,
    b.chop1date              AS 就診日,
    RTRIM(b.chop1room)       AS 診間,
    RTRIM(b.chop1mrno)       AS 病歷號,
    RTRIM(b.chop1pname)      AS 病患姓名,
    o.rlop4ordtot + o.rlop4ordtot2 AS 數量,
    (o.rlop4sub1 + o.rlop4sub2 + o.rlop4sub3 +
     o.rlop4sub4 + o.rlop4sub5 + o.rlop4sub6)
       / (o.rlop4ordtot + o.rlop4ordtot2) AS 單價,
    o.rlop4sub1 + o.rlop4sub2 + o.rlop4sub3 +
    o.rlop4sub4 + o.rlop4sub5 + o.rlop4sub6 AS 總金額,
    RTRIM(o.chop4ordno)      AS 批價代碼,
    RTRIM(o.chop4ordname)    AS 批價碼名稱,
    RTRIM(o.chop4cdate)      AS 開單時間
FROM opdordtbl o
JOIN opdbasictbl b
  ON o.chop1date = b.chop1date
 AND o.chop1time = b.chop1time
 AND o.chop1room = b.chop1room
 AND o.intop1no  = b.intop1no
LEFT JOIN gendcttypetbl t
  ON o.chop4pfin2 = t.chdcttype
LEFT JOIN gensectiontbl s
  ON b.chop1sec = s.chsecno
WHERE b.chop1date BETWEEN :strSDate AND :strEDate
  AND (b.chop1room IN ('6F4', '6021') OR b.chop1sec LIKE '0294%')
  AND b.chop1mrno NOT IN ('C36979', '1000000')
  AND o.chop4stat <> 'DC'
  AND o.chop4ordno NOT IN ('ACC-69', 'ACC-64')
  AND o.rlop4ordtot + o.rlop4ordtot2 <> 0

UNION ALL

SELECT
    RTRIM(d.chop3pfin2),
    RTRIM(t.chdcttypename),
    RTRIM(s.chnewsecno),
    RTRIM(d.chop3drid),
    '',
    b.chop1date,
    RTRIM(b.chop1room),
    RTRIM(b.chop1mrno),
    RTRIM(b.chop1pname),
    d.rlop3drgtot AS qty,
    (d.rlop3sub1 + d.rlop3sub2 + d.rlop3sub3 +
     d.rlop3sub4 + d.rlop3sub5 + d.rlop3sub6)
       / d.rlop3drgtot AS unitprice,
    d.rlop3sub1 + d.rlop3sub2 + d.rlop3sub3 +
    d.rlop3sub4 + d.rlop3sub5 + d.rlop3sub6 AS amt,
    RTRIM(d.chop3drgno),
    RTRIM(d.chop3drgname),
    RTRIM(d.chop3cdate)
FROM opddrgtbl d
JOIN opdbasictbl b
  ON d.chop1date = b.chop1date
 AND d.chop1time = b.chop1time
 AND d.chop1room = b.chop1room
 AND d.intop1no  = b.intop1no
LEFT JOIN gendcttypetbl t
  ON d.chop3pfin2 = t.chdcttype
LEFT JOIN gensectiontbl s
  ON b.chop1sec = s.chsecno
WHERE b.chop1date BETWEEN :strSDate AND :strEDate
  AND (b.chop1room IN ('6F4', '6021') OR b.chop1sec LIKE '0294%')
  AND b.chop1mrno NOT IN ('C36979', '1000000')
  AND d.chop3stat <> 'DC'
  AND d.rlop3drgtot <> 0
ORDER BY 責任中心代碼, 開單醫師代碼, 執行醫師代碼,
         就診日, 診間, 病歷號, 批價代碼, 批價碼名稱;
```

`:strSDate`、`:strEDate` 是本文為閱讀而使用的符號；原 VB6 是直接把值串入 SQL。

### 5.3 運算邏輯

1. 第一段查 `OpdOrdTbl`，第二段查 `OpdDrgTbl`。
2. 兩段投影成相同的 16 欄後用 `UNION ALL` 合併；不做去重，因為每筆醫令/藥品都是有效明細。
3. 健管範圍採聯集條件：診間是 `6F4`/`6021`，或原科別以 `0294` 開頭。
4. 透過 `GenSectionTbl` 將舊科別轉為 `chNewSecNo`，Excel 顯示新責任中心。
5. 記帳名稱用 LEFT JOIN；代碼表沒有資料時仍保留明細，記帳名稱為 NULL。
6. 總金額是 `Sub1` 到 `Sub6` 的總和。
7. 單價是 `總金額 / 數量`。SQL 先排除數量為 0，避免除以零。
8. 醫令排除 `ACC-69 欠款繳回`、`ACC-64 合約沖銷`，註解指出它們會造成數量為 0。
9. 藥品沒有執行醫師欄位，使用空字串維持 UNION 欄位位置。

### 5.4 值得注意的問題

- 藥品註解指出住院小單位會寫入 `rlOp3DrgTot2`，但目前門診 SQL 只用 `rlOp3DrgTot`；若資料規格已改，需確認數量與單價是否少算。
- `chOp4Stat <> 'DC'`、`chOp3Stat <> 'DC'` 對 NULL 的結果不是 True；狀態為 NULL 的資料不會被選入。若業務上 NULL 代表有效，應改成 `NVL(status,'') <> 'DC'` 或明確包含 NULL。
- 金額欄任一項為 NULL 時，Oracle 加總運算會得到 NULL；需確認六個 `Sub` 欄位是否保證為 0 而非 NULL。
- 病歷號 `C36979`、`1000000` 是硬編碼排除，應確認它們是測試/公用病歷，並改由設定管理。

## 6. C172 健康管理中心金額統計

### 6.1 功能目的

C172 與 C171 使用相近來源，但輸出粒度較粗：按照「責任中心 + 就診日 + 批價代碼 + 批價碼名稱」彙總總金額，不輸出病患、醫師與數量。

### 6.2 重組後 SQL

```sql
SELECT
    RTRIM(s.chnewsecno)    AS 責任中心代碼,
    b.chop1date            AS 就診日,
    RTRIM(o.chop4ordno)    AS 批價代碼,
    RTRIM(o.chop4ordname)  AS 批價碼名稱,
    SUM(o.rlop4sub1 + o.rlop4sub2 + o.rlop4sub3 +
        o.rlop4sub4 + o.rlop4sub5 + o.rlop4sub6) AS 金額
FROM opdordtbl o, opdbasictbl b, gensectiontbl s
WHERE o.chop1date = b.chop1date
  AND o.chop1time = b.chop1time
  AND o.chop1room = b.chop1room
  AND o.intop1no  = b.intop1no
  AND b.chop1sec  = s.chsecno
  AND b.chop1date BETWEEN :strSDate AND :strEDate
  AND (b.chop1room IN ('6F4', '6021') OR b.chop1sec LIKE '0294%')
  AND b.chop1mrno NOT IN ('C36979', '1000000')
  AND o.chop4stat <> 'DC'
  AND o.chop4ordno NOT IN ('ACC-69', 'ACC-64')
GROUP BY s.chnewsecno, b.chop1date, o.chop4ordno, o.chop4ordname
HAVING SUM(o.rlop4sub1 + o.rlop4sub2 + o.rlop4sub3 +
           o.rlop4sub4 + o.rlop4sub5 + o.rlop4sub6) <> 0

UNION ALL

SELECT
    RTRIM(s.chnewsecno),
    b.chop1date,
    RTRIM(d.chop3drgno),
    RTRIM(d.chop3drgname),
    SUM(d.rlop3sub1 + d.rlop3sub2 + d.rlop3sub3 +
        d.rlop3sub4 + d.rlop3sub5 + d.rlop3sub6)
FROM opddrgtbl d, opdbasictbl b, gensectiontbl s
WHERE d.chop1date = b.chop1date
  AND d.chop1time = b.chop1time
  AND d.chop1room = b.chop1room
  AND d.intop1no  = b.intop1no
  AND b.chop1sec  = s.chsecno
  AND b.chop1date BETWEEN :strSDate AND :strEDate
  AND (b.chop1room IN ('6F4', '6021') OR b.chop1sec LIKE '0294%')
  AND b.chop1mrno NOT IN ('C36979', '1000000')
  AND d.chop3stat <> 'DC'
GROUP BY s.chnewsecno, b.chop1date, d.chop3drgno, d.chop3drgname
HAVING SUM(d.rlop3sub1 + d.rlop3sub2 + d.rlop3sub3 +
           d.rlop3sub4 + d.rlop3sub5 + d.rlop3sub6) <> 0
ORDER BY 責任中心代碼, 就診日, 批價代碼, 批價碼名稱;
```

### 6.3 運算邏輯

- 醫令與藥品分別彙總，再以 `UNION ALL` 合併。
- `GROUP BY` 粒度包含日期，所以相同批價碼跨日不會被合成一筆。
- `HAVING 金額 <> 0` 移除同一組內正負沖銷後為 0 的項目。
- `GenSectionTbl` 使用內連接語意；找不到科別對照的就診資料會整筆消失，與 C171 的 LEFT JOIN 行為不同。
- 醫令分支排除 `ACC-69`、`ACC-64`；藥品分支沒有這類 ACC 醫令碼。

### 6.4 與 C171 的對帳關係

在相同日期及相同資料狀態下，理論上：

```text
C171 依責任中心/日期/批價碼分組後的「總金額」加總
≈ C172 相同群組的「金額」
```

但兩者可能因下列差異不完全相等：

- C171 的科別對照是 LEFT JOIN；C172 是內連接。
- C171 排除零數量；C172 沒有排除零數量，只排除彙總金額為 0。
- NULL 狀態、NULL 金額欄及資料在查詢期間異動都可能造成差異。

## 7. C173 健檢人次

### 7.1 功能目的

C173 計算每月、每個新科別的「就診人次」。它不是計算醫令筆數，內層先用 `DISTINCT` 壓成一個就診鍵，再由外層 `COUNT(*)`。

### 7.2 重組後 SQL

```sql
SELECT
    SUBSTR(chop1date, 1, 5) AS 就診月份,
    RTRIM(chop1sec)         AS 科別,
    COUNT(*)                AS 人次
FROM (
    SELECT DISTINCT
        b.chop1date,
        b.chop1time,
        b.chop1room,
        b.intop1no,
        s.chnewsecno AS chop1sec
    FROM opdbasictbl b,
         opdordtbl o,
         gensectiontbl s
    WHERE b.chop1date = o.chop1date
      AND b.chop1time = o.chop1time
      AND b.chop1room = o.chop1room
      AND b.intop1no  = o.intop1no
      AND b.chop1sec  = s.chsecno
      AND b.chop1date BETWEEN :strSDate AND :strEDate
      AND b.chop1room NOT IN ('AAAA', 'RRRR', 'SSSS', 'ZZZZ')
      AND b.chop1mrno NOT IN ('C36979', '1000000')
      AND b.chop1sec LIKE '0294%'
      AND RTRIM(o.chop4dcdate) IS NULL
      AND o.chop4stat <> 'DC'
)
GROUP BY SUBSTR(chop1date, 1, 5), chop1sec;
```

### 7.3 人次算法

內層 DISTINCT 的就診唯一鍵為：

```text
就診日 + 時間 + 診間 + 序號 + 新科別
```

同一次就診通常會有多筆 `OpdOrdTbl` 醫令；`DISTINCT` 會把它們壓成一列，因此外層 `COUNT(*)` 比較接近「就診人次」，而不是「醫令數」。

外層以 `SUBSTR(chOp1Date,1,5)` 取民國年月：

- `1150803` → `11508`。
- 即使使用者查跨月區間，也會分月輸出。

### 7.4 篩選邏輯

- 只接受原科別 `b.chOp1Sec LIKE '0294%'`；不像 C171/C172，診間 `6F4/6021` 本身不足以納入。
- 排除診間 `AAAA`、`RRRR`、`SSSS`、`ZZZZ`。
- 排除病歷號 `C36979`、`1000000`。
- 必須至少存在一筆符合條件的 `OpdOrdTbl` 醫令。
- 醫令的取消日期必須為空，且狀態不可為 `DC`。

### 7.5 可能的統計落差

- 只有藥品、沒有 `OpdOrdTbl` 醫令的就診不會被計數。
- 同一病患同日有不同時間/診間/序號會計為多次，這通常是合理的就診人次，但不是「不重複病患數」。
- 篩選用舊科別 `b.chOp1Sec LIKE '0294%'`，輸出卻用 `s.chNewSecNo`；科別改碼後需確認歷史對照是否仍正確。
- `RTRIM(chOp4DCDate) IS NULL` 已排除有取消日期的醫令；再加 `chOp4Stat <> 'DC'` 是雙重取消判斷。
- 輸出沒有 `ORDER BY`，Excel 列順序不保證固定。

## 8. C174 健康管理中心合約單位記帳表

### 8.1 功能目的

C174 不直接讀 `OpdBasicTbl`、`OpdOrdTbl` 或 `OpdDrgTbl`。它讀取已由合約單位記帳流程整理好的 Oracle 報表表 `OpdRecRpt_PFin2SumDM1`，輸出指定會計日期區間的明細。

### 8.2 完整 SQL

```sql
SELECT
    RTRIM(chop1pfin2)   AS 記帳代碼,
    RTRIM(chop1pfin2nm) AS 記帳名稱,
    chop1date           AS 就診日,
    RTRIM(chop1mrno)    AS 病歷號,
    RTRIM(chop1pname)   AS 病患姓名,
    RTRIM(chop1psecnm)  AS 科別名稱,
    RTRIM(chop1dridnm)  AS 醫師名稱,
    RTRIM(chop1dct)     AS 會計科目代碼,
    RTRIM(chop1dctnm)   AS 會計科目名稱,
    rlop1sub3           AS 優待金額,
    rlop1sub2           AS 記帳金額,
    rlop1subamt         AS 總金額,
    RTRIM(chcuser)      AS 記帳員
FROM opdRecRpt_PFin2SumDM1
WHERE chdateflag BETWEEN :strSDate || '000000'
                     AND :strEDate || '999999';
```

原程式實際組合範例：

```text
起日 = 1150801，迄日 = 1150803
chDateFlag BETWEEN '1150801000000' AND '1150803999999'
```

### 8.3 `chDateFlag` 的意義

上游 C23 產生資料時：

```vb
intI = intI + 1
RdoServer!chDateFlag = strSDate & Format(intI, "000000")
```

也就是：

```text
chDateFlag = 7 碼會計日 + 6 碼當日流水號
```

因此 C174 的 `000000`～`999999` 是用字串範圍涵蓋該日期的所有流水號。這裡篩選的是「彙總資料產生/會計日」，不一定等同欄位 `chOp1Date` 的原始就診日。

### 8.4 金額欄位

上游寫入 `OpdRecRpt_PFin2SumDM1` 時：

```vb
If DCDate = strSDate Then
    rlOp1Sub3 = rlOp1Sub3 - rlOp4Sub3
    rlOp1Sub2 = rlOp1Sub2 - rlOp4Sub5
Else
    rlOp1Sub3 = rlOp1Sub3 + rlOp4Sub3
    rlOp1Sub2 = rlOp1Sub2 + rlOp4Sub5
End If

rlOp1SubAMT = rlOp1Sub2 + rlOp1Sub3
```

意義：

- `rlOp1Sub3`：優待/折扣金額。
- `rlOp1Sub2`：合約記帳金額，實際由來源 `Sub5` 累計。
- `rlOp1SubAMT`：前兩者相加。
- 若當天是 DC/沖銷日，金額以負數方向寫入；否則以正數方向寫入。

### 8.5 記帳代碼重分類

上游 C23 不一定原樣保留 `chOp4PFin2`，還會依診間、醫令碼、特殊支付碼及研究案號重新分類：

| 條件                         | 寫入代碼            | 名稱                 |
| -------------------------- | --------------- | ------------------ |
| 診間 `EEEE` 且 PFin2 不是 `118` | `ZZ`            | 聯盟代檢               |
| 醫令 `00-039`                | `XX`            | 老人照護鑑定             |
| 醫令 `64-001`～`64-005`       | `YY`            | 殘障鑑定               |
| 醫令 `102-23`、`102-24`       | `WW`            | 北縣 65 歲以上老人健檢      |
| 醫令 `S001A`、`S001B`         | `42`            | 移植用組織捐贈專戶          |
| 特殊支付 `SPay=6`              | `VV`            | 維康記帳               |
| 特殊支付 `SPay=7`              | 研究案號或 `TT`      | 研究經費               |
| PFin2=`00` 的特定分支           | `UU` 或舊邏輯的 `VV` | 其他或維康記帳            |
| 其他                         | 原 `PFin2`       | `GenDctTypeTbl` 名稱 |

所以 C174 的「記帳代碼」是業務分類後的結果，不能直接視為原始醫令上的 PFin2。

### 8.6 重要發現：C174 沒有健康管理中心篩選條件

C171/C172 會限制：

```sql
b.chOp1Room IN ('6F4','6021') OR b.chOp1Sec LIKE '0294%'
```

C173 也至少限制：

```sql
b.chOp1Sec LIKE '0294%'
```

但 C174 只有 `chDateFlag` 日期條件，沒有診間、科別、責任中心或特定合約代碼條件。`OpdRecRpt_PFin2SumDM1` 的上游 C23 又是一般門急診合約記帳彙總流程，不是健康管理中心專用表。

因此依目前靜態程式判讀，C174 可能輸出指定會計日期內的全部門診合約記帳明細，而不只健康管理中心資料。除非正式資料環境另有未出現在 repo 中的 view、trigger、權限或資料生成限制，否則這是報表名稱與 SQL 範圍不一致的高優先確認項目。

建議在測試環境執行：

```sql
SELECT chop1psecnm, COUNT(*), SUM(rlop1subamt)
FROM OpdRecRpt_PFin2SumDM1
WHERE chDateFlag BETWEEN :date || '000000' AND :date || '999999'
GROUP BY chop1psecnm
ORDER BY chop1psecnm;
```

確認輸出是否包含非健管科別；若確定只應顯示健管資料，新版必須依可靠的科別/責任中心欄位補上條件，不能僅由報表所在選單推定資料範圍。

## 9. C174 上游：`OpdRecRpt_PFin2SumDM1` 如何產生

### 9.1 入口與重跑

彙總表由 C23 的 `SubOpdRecRpt_PFin2SumDM` 產生。單日重跑時先刪除指定會計日：

```sql
DELETE FROM OpdRecRpt_PFin2SumDM1
WHERE chDateFlag BETWEEN :date || '000000'
                     AND :date || '999999';
```

然後以可更新 RDO Recordset 開啟空集合：

```sql
SELECT * FROM OpdRecRpt_PFin2SumDM1 WHERE 1 = 2;
```

逐筆查詢來源資料後 `AddNew`/`Update` 寫回 Oracle。

### 9.2 主要來源資料

- `OpdOrdTbl`：非藥品醫令。
- `OpdDrgTbl`：藥品。
- `OpdBasicTbl`：病歷號、姓名、醫師、科別。
- `GenSectionTbl`：科別名稱。
- `GenDctTypeTbl`、`GenDctTbl`：記帳身分與是否允許記帳。
- `GenDctItemTbl`：會計科目名稱。
- 住院分支則改用 `IpdOrdTbl`、`IpdDrgTbl`、`IpdBasicTbl`、`GenIpdDctTypeTbl`、`GenIpdDctTbl`，並可能使用 `IpdAccCaseDayTbl` 判定收帳時間。

### 9.3 來源 SQL 的主要分支

C23 會分別處理：

1. 記帳身分、記帳會計科目的醫令。
2. 記帳身分、記帳會計科目的藥品。
3. 身分不是記帳，但會計科目被定義為記帳的醫令。
4. 身分不是記帳，但會計科目被定義為記帳的藥品。
5. 住院收帳與先前收帳沖回的正負帳。

門診主要條件包括：

```sql
-- 醫令
FROM OpdOrdTbl a, GenDctTypeTbl/GenDctTbl b, GenDctItemTbl c
WHERE a.chOp4PFin2 = b.chDctType
  AND a.chOp4Dct   = c.chDctItem
  AND a.rlOp4Sub5 <> 0
  AND (a.chOp4Proj NOT IN ('I','S','D') OR RTRIM(a.chOp4Proj) IS NULL)

-- 藥品
FROM OpdDrgTbl a, GenDctTypeTbl/GenDctTbl b, GenDctItemTbl c
WHERE a.chOp3PFin2 = b.chDctType
  AND a.chOp3Dct   = c.chDctItem
  AND a.rlOp3Sub5 <> 0
  AND (a.chOp3Stat NOT IN ('09','10','11','12') OR RTRIM(a.chOp3Stat) IS NULL)
  AND (a.chOp3Rep3Flg <> 'S' OR RTRIM(a.chOp3Rep3Flg) IS NULL)
```

日期邏輯同時檢查：

- 原就診日 `chOp1Date`。
- 入帳日期 `chOp4IDate`/`chOp3IDate`。
- 沖銷日期 `chOp4DCDate`/`chOp3DCDate`。

這是為了把「過去就診、今天才記帳」和「今天沖銷」都正確放入今日會計資料，而不是只用就診日查詢。

### 9.4 逐筆寫入流程

`RunSameRead` 對每一筆來源資料做：

1. 呼叫 `subContractKey` 維護合約記帳頭檔/回收系統資料。
2. 比較入帳日、沖銷日與就診日，排除同日完全沖銷。
3. 用就診複合鍵查 `OpdBasicTbl + GenSectionTbl`，取得病歷號、姓名、醫師及科別名稱。
4. 依規則重分類記帳代碼。
5. 寫入會計科目、名稱、建檔人員與 `chDateFlag`。
6. 依 DCDate 決定金額正負。
7. 計算 `總金額 = 記帳金額 + 優待金額`。
8. `RdoServer.Update` 寫入 `OpdRecRpt_PFin2SumDM1`。

這表示 C174 的正確性高度依賴 C23 是否已針對該日期成功產生資料。C174 自己不會重建來源表，也沒有檢查資料是否過期。

## 11. 驗證與移植建議

### 11.1 SQL 正確性驗證

1. 用同一日期分別執行 C171、C172，將 C171 分組加總後與 C172 對帳。
2. 驗證 `Sub1...Sub6` 是否可能為 NULL；若可能，改用 `NVL(SubN,0)`。
3. 確認狀態 NULL 是否代表有效；若是，修正 `status <> 'DC'`。
4. 確認 `6F4`、`6021`、`0294%`、排除病歷號與排除診間仍是現行規則。
5. 比對 C173 的「人次」與正式定義：就診次數、掛號次數、實際看診次數或不重複病患數。
6. C174 必須同時驗證 C23 重跑結果及 `chDateFlag` 範圍。

### 11.2 C# 移植建議

- 使用參數化查詢，不直接串接日期。
- 將民國日期先解析成強型別值，再依既有 schema 轉回固定 7 碼查詢參數。
- 建立共用的健康管理中心篩選規則，避免 C171/C172/C173 條件日後各自漂移。
- 將醫令與藥品投影成共同 DTO，再於資料層實作 UNION 或分查後合併。
- 將六類金額與數量公式集中封裝並補 NULL/零數量測試。
- C174 應清楚標示「資料最後產生時間」，或在授權情況下先執行/排程上游彙總。
- Excel 匯出不應依賴桌面 COM；可改用核准的 Open XML/Excel 函式庫，並明確讓使用者選擇檔案位置。
- 為每張報表建立 golden sample，比對欄位、筆數、分組金額及排序。

## 12. 結論

- C171 是健康管理中心醫令與藥品的逐筆明細。
- C172 是以責任中心、日期與批價碼彙總的金額統計。
- C173 先將醫令壓成唯一就診鍵，再計算每月科別人次。
- C174 是既有合約記帳彙總表的 Excel 查詢；其金額及分類邏輯真正發生在 C23 上游程序。

四張功能都只接受日期條件、都輸出 Excel，並未使用 Crystal Report。移植時不能只複製四段 SELECT；尤其 C174 必須連同 `OpdRecRpt_PFin2SumDM1` 的生成與重跑生命週期一起設計。
